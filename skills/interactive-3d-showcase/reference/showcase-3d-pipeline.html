五个环节，逐个对账

✓ 真跑通  ·  ◐ 本机替代  ·  ○ 未做（附原因）

1

控制 Blender ✓ 真跑通

推文：Blender MCP
用官方 blender_mcp 插件在 9876 端口收 execute_code 指令， 建模/材质/灯光/绑骨/动画全部由这几条指令依次执行完成。

2

生成 3D 资产 ◐ 本机替代

推文：TRELLIS / Hunyuan3D-2
两个模型都要求 NVIDIA GPU，这台 M4 跑不动，云 API 也没有可用 key。 改用 bpy 程序化建模：20 个部件、6,456 个顶点。

3

绑定骨骼 ◐ 本机替代

推文：UniRig（自动绑骨）
同样依赖 GPU，未跑。改用 Blender 骨架 + 按部件分配顶点组蒙皮： 4 根骨、2 秒 48 帧循环挥手动画。

4

扫描现实物体 ○ 未做

推文：COLMAP / Meshroom / gsplat
需要一组真实照片重建，这轮验证流水线没有素材，跳过。

5

发布到网页 ✓ 真跑通

推文：three.js / React Three Fiber / model-viewer
正是现在这个可交互的 3D 窗口：由 <model-viewer> 直接加载导出的 GLB，自带旋转、缩放与动画播放。

这台机器上实际发生了什么

  • 控制通道：Blender 5.2.1 LTS 以 GUI 模式启动（插件的 server 拒绝在 --background 下工作）， 客户端按 MCP 协议发 {"type":"execute_code"}，每次执行一段 Python。
  • 渲染：Cycles + Metal GPU，900×1100、110 采样，单帧约 4–5 分钟。 渲染这一步改在 --background 里做——GUI 模式下阻塞渲染会卡住控制通道。
  • 导出：glTF 2.0 GLB，仅选 Robot + Rig，不含灯光与地面，export_animations 带出 Wave 动作。
同一场景的 Cycles 静帧（第 9 帧，挥手最高点）。
网页里的 3D 模型是导出的 GLB 实时渲染，这张则是离屏渲染管线跑通的凭证。
